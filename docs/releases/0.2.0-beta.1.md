# Little Rest 0.2.0-beta.1 — internal release notes

**Build:** `0.2.0-beta.1+2` · **Date:** 21 October 2026 · **Channel:** internal Android QA / feature branch `feat/spark-personal-cloud-light-ui`.

> This is a *pre-release development milestone*, not a production family release. G2 security and G3 physical UX gates are not approved. Do not record real infant data.

## Highlights

- Beautiful, calm Today, History, Trends, Settings with bundled Inter font and support for dark/light appearance.
- **Fix:** Active sleep timer and idle hero surfaces now use warm light colors with high-contrast ink when Light is selected, instead of remaining in dark-mode indigo.
- Private single-user Spark journal via Firebase Auth + Firestore, offline persistence, conflict/undo, data export, account recovery and staged account deletion.
- Android debug staging builds are signed reproducibly on GitHub; `.staging` installs alongside the existing preview without uninstalling it.
- New editorial README hero and gallery use genuine empty-state Android screenshots, with device chrome cropped and image provenance recorded.

## Family features: implemented, but not live on Spark

The reviewed F2 **family emulator** backend and Flutter screens implement real household creation, email-verified invitations, one-time redemption, owner-authorized member revocation, shared immutable sleep operations, offline reconciliation, household deletion and account deletion.

These controls are *already interactive when the family backend is actually configured*. The personal Spark build does **not** switch on these actions because its trusted Cloud Functions are not deployed. Deploying Cloud Functions needs a Firebase **Blaze** project and billing authorization. Enabling clickable but unprotected family controls in the Spark build would misrepresent security and could expose children’s data.

To turn family sharing on for actual Android/iPhone users, this release still needs:
1. Explicit owner consent to provision a billing-linked family QA Firebase project (not the existing free Spark project), plus verified spending controls.
2. Register Android/iPhone App Check attestations and deploy reviewed functions, Firestore rules, quota secret, TTL configuration, and deletion site.
3. Sign a family-connected Android APK and iPhone build with the proper registered app identifiers.
4. Run the real two-caregiver on-device invitation/permissions/offline/revoke/delete acceptance suite.
5. Record independent G2/G3 approval before sharing with real families.

See `docs/FIREBASE_RELEASE_READINESS.md` and `docs/F2_IMPLEMENTATION.md`. No Spark → Blaze change, live Functions deployment or insecure membership-rule workaround is part of this milestone.

## Installation

For Android synthetic QA, download the **latest successful** [Spark staging APK artifact](https://github.com/analienx/baby-sleep-tracker/actions/workflows/spark-staging-android.yml); the artifact is a ZIP containing `app-debug.apk` and is retained for a limited period. Existing staging installations must be updated with the same QA signing certificate. Production Play Store and iOS TestFlight packages do not yet exist.

For an authorized Windows QA workstation, the repeatable deployment helper is:

```powershell
python scripts/staging_deploy.py doctor
python scripts/staging_deploy.py deploy
```

The once-only `configure` step has already been completed locally by the operator. Never commit Firebase private configuration or signing keys.

## Compatibility

No automatic migration exists between the memory-only preview, personal Spark and family backend environments. These are distinct storage modes and Firebase scopes. Linking an anonymous identity to email/password is essential before reinstalling or restoring on a second device.

## Release governance

This release is not final and must not receive a production approval tag. Its draft GitHub Release may be used only as a QA handoff; full acceptance requires the remaining security and usability evidence.
