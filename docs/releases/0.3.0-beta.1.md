# Little Rest 0.3.0-beta.1 — multiple babies

2026-10-22. Internal QA candidate, not a public production release. Synthetic data only until G2/G3 and physical testing.

One Firebase Spark project can support many unrelated families, each with separate Firebase Auth accounts and private Firestore permissions. Within a household, the owner creates baby profiles. Approved caregivers use their own accounts and can switch among the household's babies.

## Added

- Visible child selector above Today, History and Trends, with a separate sleep journal for each baby.
- Owner-only add/rename; verified caregivers can select a child and record sleep but cannot edit profiles.
- No migration: existing records remain Baby 1 in the original legacy operations collection. Additional babies use nested operations collections under their own profile documents.
- Child selection stored per signed-in actor and household owner; server verification before restoring a previously selected non-primary baby.
- Full account erasure attempts to remove all child journals/profiles only after the irreversible deletion fence, followed by original sleep history and Auth identity.
- Adversarial Firestore Rules tests for identity spoofing, profile tampering, child-scoped operations, and post-fence denial.

## Acceptance

Exact-source Flutter CI, Firestore Rules security, two-account Android emulator E2E and PWA CI must pass before deploying new Rules or builds. Physical Android ↔ iPhone PWA multi-child switching, offline sync, revocation, account recovery, privacy/App Check and G2/G3 review remain open.

No individual child deletion or cross-child journal migration in this release.

See the multi-baby architecture at ../MULTI_BABY_SPARK.md and implementation PR #34:

## QA rollout

Android: a signed staging APK from the GitHub Spark staging Android workflow built specifically from the multi-baby branch; do not clear old app data.

iPhone: after a matching reviewed Hosting rollout, open https://little-rest-ios-qa.web.app in Safari and Add to Home Screen. Existing PWA staging has to be updated separately; a compiled GitHub web build is not itself a live deployment.

Each caregiver uses their own verified account and the household owner explicitly authorizes sharing. No extra Firebase project or Cloud Functions are required per baby.
